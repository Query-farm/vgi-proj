# PROJ examples

[01 · When is a 10 km map ruler really 10 km?](01_when_a_map_ruler_lies.ipynb)
compares identical Web Mercator segments across latitude with WGS84 ellipsoidal
distances, tests a spherical scale approximation, and measures the same endpoints
in a suitable local UTM CRS. The three SVG figures retain the original investigation.
Returned CRS names/units establish the coordinate contract; initial bearings explain
why a horizontal map line is not a constant geodesic heading. The general transform
also measures an explicitly chosen CRS alongside automatic UTM selection.

[Open in Colab](https://colab.research.google.com/github/Query-farm/vgi-proj/blob/main/notebooks/01_when_a_map_ruler_lies.ipynb),
run the install cell, then **Run all**. Coordinates are generated by visible SQL;
no clone, map service, private data or companion file is required. The base shared
package preserves compatible Colab data/plotting libraries. Hosted Colab itself has
not been tested; fresh Python 3.12 notebook-only execution with preloaded libraries
is validated separately.

For a local run, install Python 3.11+ and [uv](https://docs.astral.sh/uv/), then:

```sh
cd notebooks
uv sync --locked --extra runner
uv run --locked --extra runner vgi-notebooks
```

The optional `runner` extra provides a local execution kernel. To register an
interactive kernel use `uv run --locked --extra runner python -m ipykernel install
--user --name vgi-proj-notebooks --display-name 'VGI PROJ notebooks'`; select it in
Jupyter, restart and run all after changing parameters.

The worker runs separately from the notebook kernel:

```sql
INSTALL vgi FROM community;
LOAD vgi;
ATTACH 'proj' (TYPE vgi,
  LOCATION 'uvx --python 3.13 --from git+https://github.com/Query-farm/vgi-proj@v0.4.0 vgi-proj-worker');
```

The shared package supplies `uvx`; first use fetches Python 3.13 and the released
worker's declared dependencies. The pyproj wheel includes PROJ and data, so no
native build or local worker checkout is required. No `--with` dependency overrides
are needed. Resolved worker versions are recorded in coverage provenance. All
coordinate calculations are local after installation. The notebook uses Haybarn
2.0.0rc11 with an empty temporary SQL-secret directory, persistent secrets disabled,
and explicit connection/worker cleanup. Validation runs on macOS Apple silicon.

## One-parameter experiment

Keep `MAP_LENGTH_M=10000.0` and change only the focus latitude from 45°N to 60°N:

```sh
uv run --locked --extra runner vgi-notebooks \
  --parameters '{"FOCUS_LATITUDE_DEG":60.0}' \
  --output-dir validation/latitude-60
```

The unchanged map ruler spans about 7.083 km at 45°N and 5.013 km at 60°N; its
map/geodesic ratio rises from 1.4118 to 1.9950. The background sweep and first figure
stay unchanged. Compare the UTM signed metre error as well as its percentage error
and the initial geodesic bearing. Reset `FOCUS_LATITUDE_DEG=45.0` for the default.

Accepted focus latitude is 0–75°N inclusive. `MAP_LENGTH_M` accepts finite lengths
from 100 to 50,000 Web Mercator metres; booleans and non-finite values are rejected.
Every midpoint is at longitude −123°, near UTM zone 10N's central meridian. The
notebook never subtracts automatic UTM coordinates with different returned EPSG
identifiers. The general `transform` requires constant CRS identifiers; a per-row
CRS column cannot replace them.

The shared [standard](https://github.com/Query-farm/vgi-example-notebooks/blob/v0.3.6/docs/standard.md)
and runner are pinned at **v0.3.6**, without copied presentation or execution helpers.
Native SVG outputs also have content-addressed `charts/` assets for GitHub. Retain
historical chart assets when updating examples. Experiment copies keep native SVG;
invalid overrides and failed execution preserve the last successful default.

[Coverage evidence](coverage.json) records eight of eight public SQL surfaces for
both release v0.4.0 and the reviewed current-public revision. `coverage/` contains
complete function/table/view exports, successful execution hashes and explicit
narrative reviews. Current-source catalog discovery is separate from the published
release used by the notebook. The reviewed source changes affect examples and CRS
argument documentation, without changing function registrations or domain logic.

The synthetic endpoint construction is not a surveyed route. Geodesic distance is
shortest ellipsoidal endpoint distance, without roads, elevation or terrain; equal
coordinate units do not imply preserved ground distance. The spherical scale rule
is an approximation, and the local UTM comparison does not validate arbitrary
bearings, long routes or cross-zone subtraction. Unknown measurements remain NULL;
a valid zero distance remains zero. Twelve relationship checks cover round trips,
general/shorthand transform agreement, symmetry, CRS compatibility and bearing units.
